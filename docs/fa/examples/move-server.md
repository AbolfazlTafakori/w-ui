# انتقال پنل به سرور دیگر

چون کلیدها و پورت‌های اینترفیس‌ها در دیتابیس‌اند، پنل برگردانده‌شده برای هر مشتری همان پنل است.

**۱. سرور قدیمی** — بکاپ بگیر: نمای کلی ← **بکاپ و بازگردانی** ← *دانلود بکاپ*، یا `w-ui` ← 25 ← 1 و فایل را بیرون ببر.

**۲. سرور جدید** — مثل همیشه نصب کن. پورت، مسیر آدرس و گواهی‌اش مال خودش است: بازگردانی هیچ‌وقت راه رسیدن به پنل را عوض نمی‌کند، پس لازم نیست با سرور قدیمی یکی باشند.

**۳. بازگردانی** — روی پنل جدید، نمای کلی ← **بکاپ و بازگردانی** ← *انتخاب فایل*، آرشیو را انتخاب کن و **بازگردانی** را بزن. یا فایل را منتقل کن و `w-ui` ← 25 ← 2. پنل آرشیو را بررسی می‌کند، وضعیت فعلی را ذخیره می‌کند، با داده‌های بازگردانده دوباره بالا می‌آید و صفحه خودش بارگذاری می‌شود. با مدیرِ سرور **قدیمی** وارد شو: حساب‌ها از آرشیو می‌آیند.

آرشیو را دستی باز نکن. مسیرهای داخلش نسبت به پوشهٔ داده‌اند، پس `tar … -C /` دیتابیس را جایی می‌گذارد که پنل هرگز نگاه نمی‌کند، و بررسی‌ها و پاک‌سازی‌ای را که بازگردانی انجام می‌دهد رد می‌کند.

**۴. آدرس‌ها** — *آدرس‌های همین سرور حفظ شود* به‌طور پیش‌فرض روشن است: هر تونل endpointی را که این سرور دارد نگه می‌دارد. اگر سرور جدید هنوز تونلی ندارد، endpointهای آرشیو می‌مانند؛ آن‌وقت اگر کانفیگ مشتری‌ها دامنه دارد رکورد DNS را جابه‌جا کن، و اگر آی‌پی قدیمی را دارد *Endpoint host* هر اینترفیس (و هر هاست در هاست‌ها) را به آدرس جدید ویرایش کن. مشتری‌ها از لینک سابسکریپشن دوباره می‌گیرند.

**۵. گواهی** — سرور جدید گواهی خودش را نگه می‌دارد. اگر مشتری‌ها سابسکریپشن را از طریق دامنه می‌گیرند، روی سرور جدید برایش گواهی بگیر: `w-ui` ← 20 ← 1؛ برای آی‌پی ← 6.

سرور قدیمی می‌تواند در طول جابه‌جایی روشن بماند — هر دو همان محدودیت‌ها را از همان داده اعمال می‌کنند، و مشتری روی هر کدام همان‌جا شمرده می‌شود.
