# اولین اینترفیس، اولین مشتری

پنل تازه عمداً خالی است: بدون اینترفیس، بدون مشتری، با یک مدیر. سه قدم یک مشتری را وصل می‌کند.

## ۱. یک اینترفیس بسازید

**اینترفیس‌ها ← افزودن اینترفیس.** اینترفیس یعنی یک تونل: یک پروتکل روی یک پورت، که از یک بازه آدرس می‌دهد، روی آدرس عمومی‌ای که مشتری‌ها به آن وصل می‌شوند.

| فیلد | توضیح |
|------|-------|
| پروتکل | WireGuard یا OpenVPN |
| اینترفیس | نامش، که نام کارت شبکه‌اش هم هست (`wg0`) |
| اندپوینت | دامنه یا IPی که در کانفیگ مشتری‌ها نوشته می‌شود |
| پورت | برای WireGuard UDP؛ OpenVPN می‌تواند TCP باشد — روی ۴۴۳ از جاهایی رد می‌شود که چیز دیگری رد نمی‌شود |
| ساب‌نت | `10.66.0.0/16` حدود ۶۵٬۰۰۰ آدرس می‌دهد؛ اولی دروازه می‌شود |
| MTU | `1420` برای بیشتر شبکه‌ها مناسب است |
| DNS | به مشتری‌ها داده می‌شود، مگر اینکه حل‌کننده‌ی خود پنل روشن باشد (پیش‌فرض روشن است) |
| اینترفیس خروجی | کارت شبکه‌ی عمومی شما، معمولاً `eth0` |
| حالت | استاندارد، یا AmneziaWG — WireGuard مبهم‌شده برای شبکه‌هایی که WireGuard ساده را می‌بندند |

کلیدها خودکار ساخته می‌شوند و کلید خصوصی هرگز در چیزی که از پنل کپی کنید دیده نمی‌شود. برای OpenVPN یک مرجع صدور گواهی، گواهی سرور و کلید `tls-crypt` ساخته و همراه اینترفیس ذخیره می‌شوند، پس بکاپ دیتابیس یک بکاپ کامل است. همه‌ی فیلدها در [اینترفیس‌ها](/fa/panel/interfaces) توضیح داده شده‌اند.

## ۲. یک مشتری بسازید

**کلاینت‌ها ← افزودن کلاینت‌ها.** هر کلاینت یعنی یک مشتری و پلنش.

| فیلد | توضیح |
|------|-------|
| نام | چیزی که دنبالش می‌گردید؛ فایل‌هایش به همین نام‌اند |
| حجم | خالی یا `0` یعنی نامحدود؛ در کرنل اعمال می‌شود |
| کاربران | پلن برای چند نفر است: هر کدام یک فایل، هر فایل هر بار روی یک دستگاه |
| مدت اعتبار | از الان چقدر؛ یا **On hold** با تعداد روز، که از اولین اتصال شمرده می‌شود |
| محدودیت سرعت | دانلود، به Mbit/s؛ `0` یعنی بدون سقف |
| تمدید | هرگز، روزانه، هفتگی یا ماهانه: ترافیک هر دوره برمی‌گردد |
| شناسهٔ تلگرام | به مشتری اجازه می‌دهد درباره‌ی پلن خودش از ربات بپرسد |
| سرورهایی که این مشتری می‌تواند استفاده کند | اینترفیس‌هایی که رویشان است — یکی یا چند تا |

**آماده**‌ها یک پلن معمول را با یک کلیک پر می‌کنند. **بیشتر ← افزودن گروهی** تا ۲۰۰ مشتری را با یک پیشوند نام و یک تعداد یک‌جا می‌سازد. همه‌ی فیلدها در [کلاینت‌ها](/fa/panel/clients) توضیح داده شده‌اند.

## ۳. کانفیگ را تحویل بدهید

روی ردیف مشتری:

- **کد QR** — برای هر کاربر، روی هر اینترفیس (و هر هاست) یکی؛ گوشی با برنامه‌ی WireGuard یا AmneziaWG اسکنش می‌کند.
- **اطلاعات کلاینت** — همه‌ی فایل‌ها و لینک‌ها، برای کپی یا دانلود.
- **لینک سابسکریپشن** — یک آدرس که مشتری نگه می‌دارد. صفحه‌ی پشتش همه‌ی فایل‌ها را با کد QR، به زبان مشتری و با قالبی که انتخاب کرده‌اید، فهرست می‌کند؛ برنامه‌هایی که سابسکریپشن می‌فهمند خودشان دوباره می‌گیرندش، پس تغییری که بعداً بدهید بدون فایل تازه به آنها می‌رسد.

کدام برنامه روی کدام دستگاه: [برنامه‌های کاربر](/fa/guide/client-apps).

## معنی وضعیت‌ها

| وضعیت | یعنی |
|-------|------|
| `active` | کار می‌کند |
| `disabled` | شما خاموشش کرده‌اید |
| `exhausted` | حجمش را مصرف کرده |
| `expired` | از تاریخ پایانش گذشته |

هر وضعیتی جز `active` فایل‌های مشتری را از کرنل برمی‌دارد، پس ترافیکش رد نمی‌شود. ترافیک یا زمان بیشتر، بازنشانی یا تمدید فوراً برش می‌گرداند — بدون ری‌استارت، بدون فایل تازه.

## OpenVPN چه فرقی دارد

WireGuard فایل مشتری را با کلیدش می‌شناسد. مشتری‌های OpenVPN نام کاربری و رمز می‌گیرند و **گواهی جداگانه برای هر مشتری در کار نیست**: ساختن یک مشتری یک ورود اضافه می‌کند، نه گواهی‌ای که باید صادر و باطل شود. سه نتیجه دارد:

- **هر ورود مال یک نفر است** — ورود دوم با همان، اولی را می‌بندد؛
- **آدرس‌ها ثابت‌اند**، پس شمارش کرنل بعد از اتصال دوباره هم دنبال همان آدم است؛
- **قطع کردن فوری است** — ورود حذف می‌شود *و* نشست زنده بسته می‌شود.

افزودن یا حذف مشتری هرگز سرور را ری‌استارت نمی‌کند، و ری‌استارت یا به‌روزرسانی پنل هیچ کس را قطع نمی‌کند.
