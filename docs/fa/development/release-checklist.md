# چک‌لیست ریلیز

ریلیز به هر سروری می‌رسد که در پنلش **Update** را بزند، `w-ui update` را اجرا کند یا تازه نصب شود. هیچ‌کدام از این مراحل اختیاری نیست.

## ۱. قبل از هر تگی

- [ ] **CHANGELOG**: یک بخش `## [X.Y.Z] — YYYY-MM-DD` با تغییرات، زیر *Added*، *Fixed*، *Changed*، *Deprecated*، *Removed* یا *Updating* — گردش‌کار ریلیز تگِ بدون این بخش را رد می‌کند و متنش همان یادداشت ریلیز می‌شود. هر کاری که اپراتور باید دستی انجام دهد (ترتیب آپدیت، نودی که باید خودش آپدیت شود) زیر *Updating* و به زبان ساده.
- [ ] لینک مقایسهٔ `[X.Y.Z]` در پایین CHANGELOG، و جلو بردن `[Unreleased]`.
- [ ] نسخه در `docs/reference/w-ui.md` و `docs/fa/reference/w-ui.md`.
- [ ] مستندات انگلیسی و فارسی برای هر چیزی که اپراتور می‌بیند؛ `docs/reference/errors.md` برای هر پیام تازه (یک تست چک می‌کند هر پیام مستندشده در کد هست).
- [ ] تغییر در API، تنظیمات، لینک‌ها یا CLI طبق [سیاست کنار گذاشتن](./deprecation-policy).

## ۲. main سبز است

- [ ] کامیت، و یک کامیت خالی `W-UI X.Y.Z`، روی `main` هستند و push شده‌اند.
- [ ] **همهٔ جاب‌های CI روی همان کامیت سبزند**: فرانت‌اند، Go (vet، staticcheck، govulncheck، `go test -race`)، نصاب، نصب تمیز روی همهٔ توزیع‌ها، جاب‌های ارتقا (نصاب، دکمهٔ پنل و منو، از نسخهٔ قبلی و از v1.1.0)، ارتقای PostgreSQL از همهٔ نسخه‌های قبلی، و جاب سازگاری پنل و نود.
- [ ] تستی که شکسته و با بازسازی یک فایل golden یا fixture «درست» شده دوباره بررسی می‌شود: فایل‌های golden (`internal/api/testdata/routes.golden`، `cmd/wui/testdata/contract/`) فقط وقتی عوض می‌شوند که تغییر همان هدف است.

## ۳. آزمایش روی dev-latest

پیش‌انتشار `dev-latest` با هر push سبز به `main` دوباره ساخته می‌شود. قبل از تگ:

- [ ] روی یک سرور آزمایشی با نسخهٔ قبلی: `w-ui` ← **Update to Dev Channel**. پنل برمی‌گردد، مشتری‌ها وصل می‌مانند یا در زمانی که جاب ارتقا گزارش داده دوباره وصل می‌شوند، لینک‌ها جواب می‌دهند.
- [ ] از هر نوع یک مشتری وصل می‌شود: WireGuard، AmneziaWG، OpenVPN.
- [ ] اگر نود هست: پنل به هر نود می‌رسد و مشتری‌ای که روی پنل اضافه می‌شود روی نود ظاهر می‌شود.

## ۴. تگ

```bash
git tag -a vX.Y.Z -m "W-UI X.Y.Z"
```

```bash
git push origin vX.Y.Z
```

فقط وقتی مرحلهٔ ۲ سبز است. گردش‌کار ریلیز به‌هرحال چک می‌کند: اولین جابش منتظر می‌ماند CI روی `main` برای دقیقاً همان کامیتِ تگ تمام شود — هر ۳۰ ثانیه نگاه می‌کند، تا ۳۰ دقیقه — و تا سبز تمام نشود چیزی ساخته نمی‌شود. اگر قرمز تمام شد، اصلاً اجرا نشده بود یا وقت انتظار تمام شد و هنوز در حال اجرا بود، ریلیز متوقف می‌شود؛ وقتی CI سبز شد گردش‌کار را از تب Actions دوباره اجرا کن. بدون کلید امضا هم منتشر نمی‌کند.

- [ ] ریلیز هشت فایل دارد: `wui-linux-amd64` و `wui-linux-arm64`، کنار هر کدام یک `.sig`، `SHA256SUMS`، `install.sh`، `w-ui.sh`، `update.sh`.

## ۵. بعد از انتشار

- [ ] روی سروری با نسخهٔ قبلی، پنل آپدیت را پیشنهاد می‌کند و نصبش می‌کند.
- [ ] ریلیز اعلام می‌شود، با بخش *Updating* اگر دارد.
- [ ] fixture ارتقای آن اضافه می‌شود: `scripts/upgrade/make-fixtures.sh vX.Y.Z`، ورودی‌هایش از `newSinceNewestFixture` در `cmd/wui/upgrade_test.go` حذف می‌شود و نسخهٔ شروعِ جاب ارتقا جلو می‌رود.
- [ ] تگ منتشرشده هرگز جابه‌جا یا حذف نمی‌شود. اشتباه به‌صورت X.Y.Z+1 منتشر می‌شود.

## تست محافظ ریلیز بدون انتشار

چکی که گردش‌کار ریلیز اول اجرا می‌کند را می‌شود دستی اجرا کرد؛ فقط می‌خواند:

```bash
GITHUB_TOKEN=<توکنی که Actions را بخواند> go run ./tools/release ci-passed -repo AbolfazlTafakori/w-ui -sha "$(git rev-parse HEAD)"
```

تا وقتی CI در حال اجراست منتظر می‌ماند (`-every`، `-timeout`)، بعد اجرای سبز را چاپ می‌کند یا می‌گوید چرا نیست. تست‌هایش (`go test ./tools/release`) اجرای سبز، قرمز، در حال اجرا که بعد سبز یا قرمز می‌شود، اجرایی که از وقت انتظار بیشتر طول می‌کشد، اجرای دوباره، شاخهٔ دیگر و کامیت دیگر را پوشش می‌دهند و چک می‌کنند `release.yml` منتظرش می‌ماند و بدون کلید امضا شکست می‌خورد.
