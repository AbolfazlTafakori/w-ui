# نودها — بیش از یک سرور

**نود** سرور دومی است که W-UI خودش را اجرا می‌کند و با آدرسش به این پنل اضافه می‌شود. بعد از اضافه شدن همه چیز را از همین‌جا مدیریت می‌کنید: اینترفیس‌ها را *روی* نود می‌سازید، مشتری‌ها را رویشان می‌گذارید، و یک لینک سابسکریپشنِ مشتری برای هر سرور یک کانفیگ دارد. یک پلن، یک حجم، چند سرور — وقتی یکی بسته شود بقیه کار می‌کنند.

برنامه‌ی جداگانه‌ای در کار نیست. نود یک پنل کامل W-UI است؛ این پنل با همان API که شما استفاده می‌کنید و با توکنی که آن پنل صادر کرده با آن حرف می‌زند. اگر این پنل روزی نباشد، نود هنوز پنلی است که می‌شود واردش شد.

## چطور کنار هم قرار می‌گیرند

```
            اینجا وارد می‌شوید
                  │
     ┌────────────▼────────────┐          ┌─────────────────────────┐
     │   پنل  (سرور A)          │  API     │   نود   (سرور B)         │
     │   مشتری‌ها، پلن‌ها،       ├─────────►│   تونل‌هایی را که برایش  │
     │   تونل‌های A و B         │  هر      │   ساخته‌اید اجرا می‌کند   │
     │   مصرف هر دو            │◄─────────┤   مصرف را گزارش می‌دهد   │
     └─────────────────────────┘  ۲۰ ثانیه └─────────────────────────┘
              ▲                                      ▲
              │  یک لینک سابسکریپشن                   │
              └─────────── مشتری ─────────────────────┘
                    یک کانفیگ برای A و یکی برای B می‌گیرد
```

هر ۲۰ ثانیه پنل به نود می‌گوید چه چیزی باید اجرا کند — اینترفیس‌ها، حساب‌ها، محدودیت‌ها — و مصرف هر حساب را می‌خواند. هیچ چیز «دستور» نیست: اگر نود یک ساعت در دسترس نبود، دور بعدی صرفاً دوباره کل تصویر است، و شمارنده‌هایش در این مدت شمرده‌اند، پس مصرفی گم نمی‌شود.

## قبل از شروع

لازم دارید:

- **دو سرور**، هر کدام با IP عمومی. سرور A پنلی است که دارید. سرور B نود می‌شود.
- روی سرور B، **پورت‌های باز**: پورت پنلی که انتخاب می‌کنید (TCP)، و پورت‌های UDP/TCP اینترفیس‌هایی که آنجا می‌سازید.
- سرور A باید بتواند از اینترنت (یا یک لینک خصوصی) **به پورت پنل سرور B برسد**.

## قدم ۱ — W-UI را روی نود نصب کنید

روی سرور B دقیقاً مثل A نصب کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AbolfazlTafakori/w-ui/main/install.sh)
```

سؤال‌ها را مثل همیشه جواب دهید. برای نود دو چیز مهم است:

- **گواهی بگیرید.** پیش‌فرض — Let's Encrypt برای IP خود سرور — کافی است. این پنل هر بار که با نود حرف می‌زند همین گواهی را بررسی می‌کند، و همین است که نمی‌گذارد کسی سر راه توکن را بخواند. (گواهی دامنه هم همان‌قدر خوب است.)
- **Access URL** را که آخر نصب چاپ می‌شود، با پورت و مسیرش، یادداشت کنید. آدرس نود همین است.

لازم نیست روی پنل خود نود چیزی بسازید. خالی بگذاریدش؛ این پنل پرش می‌کند.

## قدم ۲ — روی نود توکن صادر کنید

توکن راهی است که این پنل با آن ثابت می‌کند اجازه‌ی مدیریت نود را دارد. آن را روی نود بسازید، به یکی از این دو روش:

- **از ترمینال سرور B:**

  ```bash
  wui token issue --name "panel A"
  ```

- **یا از پنل خود نود:** با Access URL آن وارد شوید ← **نودها** ← **ساخت توکن** ← یک نام بدهید ← کپی کنید. (توکن‌ها در **تنظیمات ← احراز هویت** هم فهرست، غیرفعال و باطل می‌شوند.)

توکن **فقط یک بار** نشان داده می‌شود. همین الان کپی‌اش کنید؛ فقط به شکل هش ذخیره می‌شود و دوباره نشان داده نمی‌شود. (اگر گمش کردید، یکی دیگر صادر کنید و قبلی را در **تنظیمات ← احراز هویت** روی نود باطل کنید.)

## قدم ۳ — نود را اینجا اضافه کنید

در پنل سرور A: **نودها** ← **افزودن نود**.

| فیلد | چه بنویسید |
|---|---|
| **نام** | هر چه دوست دارید — `Frankfurt`، `node-2`. در فهرست اینترفیس‌ها و در نام کانفیگ مشتری‌ها می‌آید. |
| **آدرس** | همان Access URL نود، همان‌طور که در مرورگر بازش می‌کنید: `https://203.0.113.9:41873/`. مسیر بعد از پورت لازم نیست؛ پورت لازم است. |
| **توکن دسترسی** | توکن قدم ۲. |
| **بررسی گواهی** | وقتی نود گواهی واقعی دارد (Let's Encrypt برای IP یا دامنه — پیش‌فرض نصب‌کننده) روی **بررسی عادی** بگذارید. برای بقیه [سه حالت](#بررسی-گواهی) را ببینید. |
| **ضریب مصرف** | `1`، مگر اینکه این سرور برای مشتری گران‌تر یا ارزان‌تر باشد — [پایین](#ضریب-مصرف). |
| **سقف ترافیک ماهانه (گیگابایت)** | فقط اگر هاستینگ ترافیک ماهانه‌ی نود را محدود می‌کند — [پایین](#سقف-ترافیک-ماهانه). |
| **اجازه‌ی آدرس داخل شبکه‌ی همین سرور** | پیش‌فرض خاموش. هر درخواست به نود توکنی با دسترسی کامل به یک پنل همراه دارد، پس آدرسی که اشتباهی تایپ شود و به داخل شبکه‌ی خود این سرور اشاره کند رد می‌شود. فقط وقتی روشنش کنید که نود واقعاً روی یک شبکه‌ی خصوصیِ تحت کنترل شماست. |

ذخیره کنید. ظرف چند ثانیه ردیف **آنلاین** می‌شود، با نسخه، مدت روشنی، پردازنده، حافظه و تأخیر نود. **بررسی فوری** همان لحظه بررسی می‌کند.

اگر **آفلاین** نشان داد، وضعیت می‌گوید کدام نوع: *refused* (پورت بسته یا پورت اشتباه)، *no answer* (فایروال یا IP اشتباه)، *wrong credentials* (توکن اشتباه)، یا *answered but is not a panel* (آدرس اشتباه — چیز دیگری روی آن پورت است). [وقتی نود ساکت می‌شود](#وقتی-نود-ساکت-می‌شود) بررسی‌ها را دارد.

## صفحه‌ی نودها

نوار بالا: **نودها**، چند تا **آنلاین** و **آفلاین** هستند، و **میانگین تأخیر** تا آنها. **مرجع صدور این پنل** (برای [mutual TLS](#اثبات-هویت-پنل-mutual-tls،-اختیاری)) و **ساخت توکن** (برای وقتی که خودِ *این* پنل قرار است به عنوان نود مدیریت شود) کنار **افزودن نود** هستند.

| ستون | چه نشان می‌دهد |
|------|----------------|
| **عملیات** | ⚡ **بررسی فوری** همان لحظه نود را بررسی می‌کند؛ **به‌روزرسانی** از نود می‌خواهد خودش را به‌روز کند (وقتی نسخه‌ی تازه‌تری هست)؛ ✎ ویرایش؛ 🗑 حذف. |
| **فعال** | کلید روشن/خاموش. نود خاموش همگام نمی‌شود و اینترفیس تازه‌ای رویش ساخته نمی‌شود. |
| **نام** | نام نود؛ ردیف خود این سرور **در حال اجرا** نوشته می‌شود. |
| **آدرس** | جایی که به آن می‌رسید، و اینکه گواهی‌اش چطور بررسی می‌شود. |
| **وضعیت** | **آنلاین** یا **آفلاین** با دلیل، و **ترافیک تمام شد** وقتی سقف ترافیکش مصرف شده. |
| **پردازنده** · **حافظه** · **نسخه** · **مدت روشنی** | همان‌طور که نود گزارش می‌دهد. |
| **ترافیک** | آنچه در این دوره جابه‌جا کرده، در کنار سقفش اگر تعیین شده باشد. |
| **تأخیر** · **آخرین بار** | زمان رفت‌وبرگشت آخرین بررسی، و آخرین باری که جواب داده. |

## قدم ۴ — روی نود اینترفیس بسازید

**اینترفیس‌ها** ← **افزودن اینترفیس** ← در فیلد **سرور** به جای *همین سرور* نود را انتخاب کنید. بقیه مثل اینترفیس محلی است: پروتکل، پورت، ساب‌نت، اندپوینت (IP عمومی نود یا نامی که به آن اشاره می‌کند).

پنل در دور بعدی آن را برای نود می‌فرستد؛ نود بالایش می‌آورد. ردیف می‌گوید روی کدام سرور است. اینترفیس بعداً به سرور دیگری منتقل نمی‌شود — همه‌ی مشتری‌هایش کانفیگشان را از دست می‌دادند — پس اول سرور را انتخاب کنید.

می‌توانید به نود چند اینترفیس بدهید (WireGuard، AmneziaWG، OpenVPN)، و هاست‌ها رویشان دقیقاً مثل اینترفیس محلی کار می‌کنند.

## قدم ۵ — مشتری‌ها را رویش بگذارید

**کلاینت‌ها** ← **افزودن کلاینت‌ها** ← زیر **سرورهایی که این مشتری می‌تواند استفاده کند** هر اینترفیسی را که مشتری می‌تواند استفاده کند تیک بزنید — روی این سرور، روی نود، یا هر دو. حجم، تاریخ پایان و تعداد کاربر مال مشتری است و بین همه مشترک.

هر فایلی که مشتری دارد روی هر اینترفیسی که به آن دسترسی دارد حساب خودش را می‌گیرد، و لینک سابسکریپشن برای هر کدام یک کانفیگ به برنامه می‌دهد. مصرف همه‌ی سرورها روی یک حجم جمع می‌شود؛ وقتی تمام شد، مشتری همه‌جا قطع می‌شود.

کارهای گروهی (الصاق مشتری‌های موجود به یک اینترفیس، جابه‌جا کردن یک گروه) بین سرورها هم همین‌طور کار می‌کنند.

### اتصال هم‌زمان، بین سرورها

**کاربران** پلن — یعنی اتصال‌های هم‌زمان — مال مشتری است نه مال یک سرور. پنل هر سه ثانیه از هر نود می‌پرسد کدام اعتبارها رویش زنده‌اند (چند بایت برای هر نشست، نه کل وضعیت)، آن را به آنچه کرنل خودش می‌بیند اضافه می‌کند، و اتصال‌های مشتری را روی همه چیز می‌شمارد — یک فایل WireGuard روی این سرور و یک ورود OpenVPN روی نود دو تا حساب می‌شوند. وقتی بیشتر از اجازه‌ی پلن وصل باشند، جدیدترین دو دقیقه کنار گذاشته می‌شود: روی این سرور مستقیماً؛ روی نود، پنل همان لحظه به نود می‌گوید (`/api/node/hold`) و با هر ارسال دوباره، و نود نشست را می‌بندد و peer را تا آن موقع خاموش نگه می‌دارد. گزارش پنل می‌نویسد `connection limit reached; device held off … on="node 2"`، و گزارش نود `device held off by the panel`.

اگر نودی در دسترس نباشد، آخرین گزارشش ۳۰ ثانیه معتبر می‌ماند و بعد شمرده نمی‌شود — دستگاه مشتری روی نودِ در دسترس نبودنی را از طریق آن هم نمی‌شود کنار گذاشت. در سمت نود، وقتی ۴۵ ثانیه از پنلش خبری نشود، خودش با همان چیزی که می‌بیند مشتری‌ها را به سقف نگه می‌دارد، تا یک قطعی کوتاه بین سرورها راهی برای دور زدن سقف نباشد. هر دو طرف باید همین نسخه یا جدیدتر باشند.

## بررسی گواهی

توکن به این پنل اجازه می‌دهد کلیدهای همه‌ی مشتری‌های آن نود را بخواند، پس اینکه *چه کسی* در آن آدرس جواب می‌دهد مهم است. سه حالت:

| حالت | کِی |
|---|---|
| **بررسی عادی** | نود گواهی‌ای دارد که مرورگر می‌پذیرد — Let's Encrypt برای IP یا دامنه‌اش. پیش‌فرض نصب‌کننده و انتخاب درست است. |
| **فقط یک گواهی مشخص** (pin) | نود گواهی خودامضا یا خصوصی دارد. **بخوانش** را بزنید تا اثر انگشتی که آدرس همین الان نشان می‌دهد گرفته شود، و آن را با خود نود مقایسه کنید (`openssl x509 -in /etc/wui/certs/<name>/fullchain.pem -noout -fingerprint -sha256` روی سرور B). از آن به بعد این پنل همان گواهی را می‌پذیرد و هیچ گواهی دیگری را، هر که امضایش کرده باشد. |
| **اصلاً بررسی نکن** | فقط روی لینک خصوصی‌ای که هیچ کس دیگری به آن نمی‌رسد. هر کسی بین دو سرور می‌تواند همه چیز را، توکن را هم، بخواند و عوض کند. |

### اثبات هویت پنل (mutual TLS، اختیاری)

به طور پیش‌فرض نود هر درخواستی را که توکن را بداند می‌پذیرد. برای اینکه **فقط همین پنل** را بپذیرد، حتی اگر توکن از یک لاگ یا بکاپ لو برود:

1. روی سرور A: **نودها** ← **مرجع صدور این پنل** ← نمایش ← کپی.
2. روی پنل خود سرور B: **تنظیمات** ← **احراز هویت** ← **پنلی که اجازه‌ی مدیریت این یکی را دارد** ← بچسبانید ← ذخیره.
3. روی سرور A، نود را ویرایش کنید و **بررسی، و اثبات هویت این پنل** را انتخاب کنید.

از آن به بعد نود درخواستی را که گواهی کلاینت این پنل را نداشته باشد رد می‌کند (`this node only accepts a managing panel that presents a client certificate`). خالی کردن آن فیلد روی نود دوباره خاموشش می‌کند.

## ضریب مصرف

اینکه هر گیگابایت از این نود چقدر از حجم مشتری کم کند. `1` همان‌طور که هست حساب می‌کند. `2` دو برابر — برای سروری که پهنای باندش برایتان گران‌تر است یا نمی‌خواهید زیاد استفاده شود. `0.5` نصف. پیش از کم شدن از حجم مشتری در آنچه نود گزارش می‌دهد ضرب می‌شود، پس پلن ۱۰ گیگی روی نودِ `2` با ۵ گیگ ترافیک تمام می‌شود. ردیف هر دستگاه در جدول مصرف مشتری هم به همین شکل ضرب می‌شود، پس جمع ردیف‌ها هنوز بایت به بایت با مصرف یکی است.

## سقف ترافیک ماهانه

اگر هاستینگ ترافیک ماهانه‌ی سرور B را محدود می‌کند، سقف را اینجا بگذارید و روزی از ماه که از نو شروع می‌شود (۱ تا ۲۸؛ `0` یعنی خودتان دستی پاکش می‌کنید). وقتی نود این‌قدر ترافیک جابه‌جا کرد، پنل همه‌ی مشتری‌ها را تا شروع دوباره از آن برمی‌دارد — ردیف **ترافیک تمام شد** می‌گوید. مشتری‌هایی که سرورهای دیگری دارند آنجا کار می‌کنند.

## به‌روزرسانی نود

نودها را همراه پنل به‌روز کنید: نودی که از پنلش قدیمی‌تر است هنوز همگام می‌شود (فیلدهایی که نمی‌شناسد نادیده گرفته می‌شوند)، ولی سقف اتصال بین سرورها و برداشتن اینترفیس‌های حذف‌شده لازم دارد هر دو طرف یک نسخه باشند.

**نودها** ← ردیف نود ← **به‌روزرسانی** (وقتی نسخه‌ی تازه‌تری هست نشان داده می‌شود). پنل از نود *می‌خواهد* خودش را به‌روز کند — **نصب و راه‌اندازی دوباره** را تأیید می‌کنید؛ نود نسخه را از GitHub می‌گیرد و امضایش را با کلیدی که داخل برنامه‌ی خودش هست بررسی می‌کند. هیچ چیزی از این پنل فرستاده نمی‌شود، پس پنلی که هک شده باشد نمی‌تواند روی نودها کد بفرستد. یا روی سرور B: `w-ui update`.

نودی که روی هر کدام از این نسخه‌هاست توکن پنل مدیرش را رد می‌کند: در دسترس نیست نشان داده می‌شود، مشتری‌هایی که اینجا اضافه می‌شوند هرگز به آن نمی‌رسند، ترافیکش شمرده نمی‌شود، و **به‌روزرسانی** هم به آن نمی‌رسد. یک بار روی خود سرور نود `w-ui update` را اجرا کنید. از ۲.۶.۱ نود دوباره از همین‌جا مدیریت و به‌روز می‌شود.
:::

## حذف نود

**نودها** ← حذف. هیچ چیزی روی سرور B عوض نمی‌شود: اینترفیس‌هایش را اجرا می‌کند و مشتری‌هایش تا وقتی روی پنل خود نود حذفشان نکنید کار می‌کنند. توکنش تا وقتی آنجا باطلش نکنید (تنظیمات ← احراز هویت) معتبر می‌ماند.

برای حذف اینترفیس‌های نود از همین‌جا، اول آنها را در **اینترفیس‌ها** حذف کنید — هر دور اینترفیس‌هایی را که نود هنوز باید داشته باشد نام می‌برد، پس اینترفیس حذف‌شده ظرف یک دور، با کارت شبکه‌اش، روی نود پایین آورده می‌شود.

## وقتی نود ساکت می‌شود

ردیف می‌گوید چه نوع سکوتی است. به ترتیب:

1. **سرور A می‌تواند به آن برسد؟** روی A: `curl -sk https://NODE-IP:PORT/api/meta` — باید JSON بگیرید. timeout یعنی شبکه یا فایروالی روی B (`ufw status`، پنل فایروال هاستینگ)؛ *connection refused* یعنی پورت اشتباه یا پنل نود خاموش است (`w-ui status` روی B).
2. **اطلاعات ورود اشتباه.** توکن باطل شده یا اشتباه تایپ شده. روی B یکی تازه صادر کنید و نود را اینجا ویرایش کنید.
3. **گواهی رد شد.** گواهی نود عوض شده (گواهی خودامضای تمدیدشده، یا نصب تازه) در حالی که حالت *فقط یک گواهی مشخص* است: اثر انگشت را دوباره بخوانید. با *بررسی عادی*، گواهی IPی که تمدید نشده: روی B، `w-ui` ← ۲۰.
4. **جواب داد ولی پنل نیست.** چیز دیگری در آن آدرس جواب می‌دهد — پورت داخل Access URL را بررسی کنید.
5. **آنلاین است ولی اینترفیس‌ها روی B پیدا نمی‌شوند.** `journalctl -u wui -f` روی A در حین یک دور، خط‌های `node …` را با دلیلش نشان می‌دهد؛ روی B، اینترفیس پورت آزاد لازم دارد و برای AmneziaWG ماژولش را — همان پیام‌های اینترفیس محلی، که در [خطاها](/fa/reference/errors) فهرست شده‌اند.

تا وقتی نودی در دسترس نیست پنل همه‌ی اطلاعات را نگه می‌دارد؛ مشتری‌های آن سرور هستند که متوجه می‌شوند. هر چه در این مدت مصرف کرده‌اند وقتی برگشت شمرده می‌شود.

## پنل خودِ نود

سرور B یک پنل کامل باقی می‌ماند. می‌توانید واردش شوید، آنجا `w-ui` را اجرا کنید، از آن بکاپ بگیرید، و اینترفیس‌ها و حساب‌هایی را که این پنل رویش گذاشته ببینید — به عنوان مدیریت‌شده علامت خورده‌اند و از اینجا ویرایش می‌شوند نه آنجا. بکاپ‌های زمان‌بندی‌شده‌اش مال خودش است؛ بازگردانی A، B را بازنمی‌گرداند.
