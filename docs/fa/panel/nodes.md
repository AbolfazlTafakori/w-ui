# نودها — بیش از یک سرور

**نود** یک سرور دوم است که W-UI خودش را دارد و با آدرس به این پنل اضافه می‌شود. بعد از اضافه شدن، همه‌چیز را از همین‌جا مدیریت می‌کنی: تانل‌ها را *روی* نود می‌سازی، مشتری‌ها را روی آن می‌گذاری، و یک لینک سابسکریپشن مشتری برای هر سرور یک کانفیگ دارد. یک پلن، یک سهمیه، چند سرور — وقتی یکی مسدود شد، بقیه کار می‌کنند.

agent جداگانه‌ای وجود ندارد. نود یک پنل کامل W-UI است؛ این پنل با همان API که خودت استفاده می‌کنی و با توکنی که آن پنل صادر کرده با آن حرف می‌زند. اگر روزی این پنل از بین برود، نود هنوز پنلی است که می‌شود به آن وارد شد.

## چطور کنار هم قرار می‌گیرند

```
            این‌جا وارد می‌شوی
                  │
     ┌────────────▼────────────┐          ┌─────────────────────────┐
     │   پنل  (سرور A)         │  API     │   نود   (سرور B)        │
     │   مشتری‌ها، پلن‌ها،       ├─────────►│   تانل‌هایی که برایش    │
     │   تانل‌های A و B         │  هر      │   ساختی را اجرا می‌کند   │
     │   مصرف از هر دو          │◄─────────┤   مصرف را گزارش می‌دهد  │
     └─────────────────────────┘  ۳۰ ثانیه └─────────────────────────┘
              ▲                                      ▲
              │  یک لینک سابسکریپشن                   │
              └─────────── مشتری ────────────────────┘
                 یک کانفیگ برای A و یکی برای B می‌گیرد
```

هر ۳۰ ثانیه پنل به نود می‌گوید چه چیزی باید اجرا کند — تانل‌ها، اکانت‌ها، محدودیت‌ها — و مصرف هر اکانت را می‌خواند. هیچ‌چیز «دستور» نیست: اگر نود یک ساعت در دسترس نبود، دور بعدی صرفاً دوباره کل تصویر است، و شمارنده‌هایش در این مدت شمرده‌اند، پس مصرفی گم نمی‌شود.

## قبل از شروع

لازم داری:

- **دو سرور**، هر کدام با IP عمومی. سرور A همان پنلی است که داری. سرور B نود می‌شود.
- روی سرور B، **پورت‌های باز**: پورت پنلی که انتخاب می‌کنی (TCP)، و پورت‌های UDP/TCP تانل‌هایی که آن‌جا می‌سازی.
- سرور A باید بتواند از اینترنت (یا لینک خصوصی) **به پورت پنل سرور B برسد**.

## قدم ۱ — W-UI را روی نود نصب کن

روی سرور B دقیقاً مثل A نصب کن:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AbolfazlTafakori/w-ui/main/install.sh)
```

سؤال‌ها را مثل همیشه جواب بده. دو چیز برای نود مهم است:

- **سرتیفیکیت بگیر.** پیش‌فرض — Let's Encrypt برای IP خود سرور — کافی است. این پنل هر بار که با نود حرف می‌زند آن سرتیفیکیت را چک می‌کند، و همین جلوی خواندن توکن در مسیر را می‌گیرد. (سرتیفیکیت دامنه هم همان‌قدر خوب است.)
- **Access URL** که آخر کار چاپ می‌شود را با پورت و مسیرش یادداشت کن. این آدرس نود است.

لازم نیست روی پنل خودِ نود چیزی بسازی. خالی بگذار؛ این پنل پرش می‌کند.

## قدم ۲ — روی نود توکن صادر کن

توکن راهی است که این پنل ثابت می‌کند اجازهٔ مدیریت نود را دارد. روی نود، به یکی از این دو راه بساز:

- **از ترمینال سرور B:**

  ```bash
  wui token issue --name "panel A"
  ```

- **یا از پنل خودِ نود:** با Access URL وارد شو → **Nodes** → **Issue token** → نامی بده → کپی کن. (توکن‌ها در **Settings → Authentication → API tokens** فهرست، غیرفعال و باطل می‌شوند.)

توکن **یک بار** نشان داده می‌شود. همین حالا کپی کن؛ فقط هش‌اش ذخیره می‌شود و دیگر قابل نمایش نیست. (اگر گمش کردی، یکی دیگر بساز و قبلی را در Settings → Authentication → API tokens روی نود باطل کن.)

## قدم ۳ — نود را این‌جا اضافه کن

در پنل سرور A: **Nodes** → **Add node**.

| فیلد | چه بنویسی |
|---|---|
| **Name** | هر چه دوست داری — `Frankfurt`، `node-2`. در فهرست تانل‌ها و نام کانفیگ مشتری‌ها می‌آید. |
| **Address** | همان Access URL نود، همان‌طور که در مرورگر بازش می‌کنی: `https://203.0.113.9:41873/`. مسیر بعد از پورت لازم نیست؛ پورت لازم است. |
| **Access token** | توکن قدم ۲. |
| **Certificate check** | وقتی نود سرتیفیکیت واقعی دارد (Let's Encrypt برای IP یا دامنه — پیش‌فرض نصاب) روی **Verify normally** بگذار. برای بقیه [سه حالت](#چک-سرتیفیکیت) را ببین. |
| **Usage multiplier** | `1`، مگر این سرور برای مشتری گران‌تر یا ارزان‌تر باشد — [پایین](#ضریب-مصرف). |
| **Transfer allowance** | فقط اگر هاست، ترافیک ماهانهٔ نود را محدود می‌کند — [پایین](#سهمیهٔ-ترافیک). |

ذخیره کن. ظرف چند ثانیه ردیف **Online** می‌شود، با نسخه، uptime، CPU، RAM و تأخیر نود. **Check now** همان لحظه چک می‌کند.

اگر **Offline** نشان داد، وضعیت می‌گوید کدام نوع: *refused* (پورت بسته یا پورت غلط)، *no answer* (فایروال یا IP غلط)، *wrong credentials* (توکن بد)، یا *answered but is not a panel* (آدرس غلط — چیز دیگری روی آن پورت است). [عیب‌یابی](#وقتی-نود-ساکت-می‌شود) چک‌ها را دارد.

## قدم ۴ — روی نود تانل بساز

**Interfaces** → **Add inbound** → در فیلد **Server** به‌جای *this server* نود را انتخاب کن. بقیه مثل تانل محلی است: پروتکل، پورت، زیرشبکه، endpoint (IP عمومی نود یا نامی که به آن اشاره می‌کند).

پنل در دور بعدی آن را به نود می‌فرستد؛ نود بالایش می‌آورد. ردیف می‌گوید روی کدام سرور است. تانل بعداً به سرور دیگری منتقل نمی‌شود — همهٔ مشتری‌هایش کانفیگشان را از دست می‌دادند — پس اول سرور را انتخاب کن.

می‌توانی به نود چند تانل بدهی (WireGuard، AmneziaWG، OpenVPN)، و هاست‌ها و گروه‌های هاست روی آن‌ها دقیقاً مثل تانل محلی کار می‌کنند.

## قدم ۵ — مشتری‌ها را رویش بگذار

**Clients** → **Add client** → زیر **Servers this customer can use** هر تانلی که مشتری می‌تواند استفاده کند را تیک بزن — روی این سرور، روی نود، یا هر دو. سهمیه، انقضا و سقف دستگاه مال مشتری است و بین همه مشترک.

هر دستگاهی که مشتری اضافه می‌کند روی هر تانلی که اجازه دارد یک اکانت می‌گیرد، و لینک سابسکریپشن برای هر کدام یک کانفیگ به اپ می‌دهد. مصرف همهٔ سرورها در یک سهمیه جمع می‌شود؛ وقتی تمام شد، مشتری همه‌جا قطع می‌شود.

عملیات گروهی (اتصال مشتری‌های موجود به یک تانل، جابه‌جایی یک گروه) هم به همین شکل بین سرورها کار می‌کند.

### اتصال هم‌زمان، بین سرورها

**اتصال هم‌زمان** پلن مال مشتری است، نه یک سرور. هر سه ثانیه پنل از هر نود می‌پرسد کدام اعتبارها رویش زنده‌اند (چند بایت برای هر نشست، نه کل وضعیت)، آن را با چیزی که کرنل خودش می‌بیند جمع می‌کند و اتصال‌های مشتری را روی همه‌چیز می‌شمارد — فایل وایرگارد روی این سرور و لاگین OpenVPN روی نود، دو اتصال است. وقتی بیشتر از سقف پلن وصل باشند، جدیدترین دو دقیقه نگه داشته می‌شود: روی این سرور مستقیم؛ روی نود، پنل همان لحظه به نود می‌گوید (`/api/node/hold`) و با هر push دوباره، و نود نشست را قطع و peer را تا آن زمان کنار می‌گذارد. لاگ پنل می‌گوید `connection limit reached; device held off … on="node 2"`، لاگ نود `device held off by the panel`.

اگر نودی در دسترس نباشد، آخرین گزارشش ۳۰ ثانیه معتبر می‌ماند و بعد شمرده نمی‌شود — دستگاه مشتری روی نود غیرقابل‌دسترس را از طریق آن هم نمی‌شود نگه داشت. در سمت نود، وقتی ۴۵ ثانیه از پنلش خبری نشود، خودش با همان چیزی که می‌بیند مشتری‌ها را به سقف نگه می‌دارد، تا یک قطعی کوتاه بین سرورها راهی برای دور زدن سقف نباشد. هر دو طرف باید این نسخه یا جدیدتر باشند.

## چک سرتیفیکیت

توکن به این پنل اجازه می‌دهد کلید همهٔ مشتری‌های آن نود را بخواند، پس *چه کسی جواب می‌دهد* مهم است. سه حالت:

| حالت | کی |
|---|---|
| **Verify normally** | نود سرتیفیکیتی دارد که مرورگر قبول می‌کند — Let's Encrypt برای IP یا دامنه‌اش. پیش‌فرض نصاب و انتخاب درست. |
| **Accept one certificate only** (pinned) | نود سرتیفیکیت self-signed یا خصوصی دارد. **Read it** را بزن تا اثرانگشتی که آن آدرس الان ارائه می‌دهد خوانده شود، و با خودِ نود مقایسه کن (`openssl x509 -in /etc/wui/certs/<name>/fullchain.pem -noout -fingerprint -sha256` روی سرور B). این پنل بعد فقط همان سرتیفیکیت را قبول می‌کند، هر کس امضایش کرده باشد. |
| **Do not check at all** | فقط روی لینک خصوصی‌ای که کس دیگری به آن نمی‌رسد. هر کسی بین دو سرور می‌تواند همه‌چیز، از جمله توکن، را بخواند و عوض کند. |

### اثبات هویت پنل (mutual TLS، اختیاری)

به‌طور پیش‌فرض نود هر کسی که توکن را بداند قبول می‌کند. برای اینکه **فقط این پنل** را قبول کند، حتی اگر توکن از لاگ یا بک‌آپ لو برود:

1. روی سرور A: **Nodes** → **This panel's authority** → **Show it** → کپی.
2. روی پنل خودِ سرور B: **Settings** → **Authentication** → **Panel allowed to manage this one** → بچسبان → ذخیره.
3. روی سرور A نود را ویرایش کن و **Verify, and prove who this panel is** را انتخاب کن.

از این به بعد نود درخواستی بدون سرتیفیکیت کلاینت این پنل را رد می‌کند (`this node only accepts a managing panel that presents a client certificate`). خالی کردن آن فیلد روی نود دوباره خاموشش می‌کند.

## ضریب مصرف

هر گیگابایت از این نود برای مشتری چقدر حساب می‌شود. `1` همان‌طور که هست. `2` دو برابر — برای سروری که پهنای باندش برایت گران‌تر است یا می‌خواهی کمتر استفاده شود. `0.5` نصف. چیزی که نود گزارش می‌دهد قبل از کم شدن از سهمیهٔ مشتری در این ضرب می‌شود، پس پلن ۱۰ گیگ روی نودِ `2` به اندازهٔ ۵ گیگ ترافیک دوام می‌آورد.

## سهمیهٔ ترافیک

اگر هاست، ترافیک ماهانهٔ سرور B را محدود می‌کند، سقف و روزِ ریست ماه را این‌جا بده (۱ تا ۲۸؛ `0` یعنی خودت دستی صفرش می‌کنی). وقتی نود به آن حد رسید، پنل تا ریست همهٔ مشتری‌ها را از رویش برمی‌دارد — ردیف **allowance spent** می‌شود. مشتری‌هایی که سرور دیگری دارند آن‌جا کار می‌کنند.

## به‌روزرسانی نود

نودها را همراه پنل به‌روز کن: نود قدیمی‌تر از پنلش هنوز sync می‌شود (فیلدهایی که نمی‌شناسد نادیده گرفته می‌شوند)، ولی سقف اتصال بین سرورها و حذف تانل‌های پاک‌شده هر دو طرف را روی یک نسخه می‌خواهد.

**Nodes** → ردیف نود → **Update** (وقتی ریلیز جدیدتری هست دیده می‌شود). پنل از نود *می‌خواهد* خودش را به‌روز کند — تو **Install and restart** را تأیید می‌کنی؛ نود ریلیز را از GitHub می‌گیرد و امضا را با کلیدی که در باینری خودش هست چک می‌کند. از این پنل هیچ چیزی نمی‌رود، پس پنلِ نفوذشده نمی‌تواند به نودها کد تحمیل کند. یا روی سرور B: `w-ui update`.

## حذف نود

**Nodes** → حذف. روی سرور B هیچ چیزی عوض نمی‌شود: تانل‌هایش را اجرا می‌کند و مشتری‌هایش کار می‌کنند تا وقتی روی پنل خودِ نود حذفشان کنی. توکنش تا وقتی آن‌جا باطلش نکنی معتبر است (Settings → Authentication → API tokens).

برای اینکه اول تانل‌های نود را از این‌جا حذف کنی، در **Interfaces** حذفشان کن — هر دور تانل‌هایی را که نود باید داشته باشد نام می‌برد، پس تانل حذف‌شده در همان دور روی نود هم، همراه با دستگاهش، پایین می‌آید.

## وقتی نود ساکت می‌شود

ردیف می‌گوید کدام نوع سکوت. به ترتیب:

1. **سرور A به آن می‌رسد؟** روی A: `curl -sk https://NODE-IP:PORT/api/meta` — باید JSON بگیری. timeout یعنی شبکه یا فایروال روی B (`ufw status`، پنل فایروال هاست)؛ *connection refused* یعنی پورت غلط یا پنل نود خاموش (`w-ui status` روی B).
2. **Wrong credentials.** توکن باطل شده یا غلط تایپ شده. روی B یکی جدید بساز و نود را این‌جا ویرایش کن.
3. **سرتیفیکیت رد شد.** سرتیفیکیت نود عوض شده (self-signed تمدیدشده، یا نصب تازه) در حالی که حالت *pinned* است: اثرانگشت را دوباره بخوان. با *Verify normally*، سرتیفیکیت IP که تمدید نشده: روی B، `w-ui` → ۲۰.
4. **Answered but is not a panel.** چیز دیگری در آن آدرس جواب می‌دهد — پورتِ Access URL را چک کن.
5. **Online است ولی تانل‌ها روی B ظاهر نمی‌شوند.** `journalctl -u wui -f` روی A هنگام یک دور، خط‌های `node …` را با دلیل نشان می‌دهد؛ روی B تانل پورت آزاد لازم دارد و برای AmneziaWG ماژول — همان پیام‌های تانل محلی، در [خطاها](/fa/reference/errors).

تا وقتی نود در دسترس نیست پنل همهٔ رکوردها را نگه می‌دارد؛ مشتری‌های آن سرور کسانی‌اند که متوجه می‌شوند. هر چه در این مدت مصرف کرده‌اند بعد از برگشت حساب می‌شود.

## پنل خودِ نود

سرور B یک پنل کامل می‌ماند. می‌توانی به آن وارد شوی، `w-ui` را آن‌جا اجرا کنی، از آن بک‌آپ بگیری، و تانل‌ها و اکانت‌هایی که این پنل رویش گذاشته را ببینی — به‌عنوان «مدیریت‌شده» علامت خورده‌اند و از این‌جا ویرایش می‌شوند، نه آن‌جا. بک‌آپ‌های زمان‌بندی‌شده‌اش مال خودش است؛ ریستور A، B را ریستور نمی‌کند.
