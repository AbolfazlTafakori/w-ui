# نودها: بیش از یک سرور

**نود** سرور دیگری است که با آدرسش به این پنل اضافه می‌شود. می‌تواند یک W-UI دیگر باشد، یا پنل 3x-ui، یا پنل پاسارگاد. بعد از اضافه شدن همه چیز را از همین‌جا مدیریت می‌کنید: تونل را *روی* نود می‌سازید، مشتری را رویش می‌گذارید، و لینک اشتراک هر مشتری برای هر سرور یک کانفیگ دارد. یک پلن، یک حجم، چند سرور؛ وقتی یکی بسته شود، بقیه کار می‌کنند.

برنامه‌ی جداگانه‌ای برای نصب نیست. نود W-UI یک پنل کامل W-UI است و این پنل با همان API که خودتان استفاده می‌کنید، و با توکنی که آن پنل صادر کرده، با آن حرف می‌زند. اگر این پنل روزی نباشد، نود هنوز پنلی است که می‌شود واردش شد.

## چطور کنار هم قرار می‌گیرند

```
            اینجا وارد می‌شوید
                  │
     ┌────────────▼────────────┐          ┌─────────────────────────┐
     │   پنل  (سرور A)          │  API     │   نود   (سرور B)         │
     │   مشتری‌ها، پلن‌ها،       ├─────────►│   تونل‌هایی را که برایش  │
     │   تونل‌های A و B         │  هر      │   ساخته‌اید اجرا می‌کند   │
     │   مصرف هر دو            │◄─────────┤   مصرف را گزارش می‌دهد   │
     └─────────────────────────┘  ۲۰ ثانیه └─────────────────────────┘
              ▲                                      ▲
              │  یک لینک اشتراک                      │
              └─────────── مشتری ─────────────────────┘
                    یک کانفیگ برای A و یکی برای B می‌گیرد
```

پنل هر ۲۰ ثانیه به نود می‌گوید چه چیزی باید اجرا کند، یعنی تونل‌ها، حساب‌ها و محدودیت‌ها، و مصرف هر حساب را می‌خواند. هیچ‌کدام دستور یک‌باره نیست. اگر نود یک ساعت در دسترس نبود، دور بعدی دوباره کل تصویر را می‌فرستد، و شمارنده‌های نود در این مدت شمرده‌اند؛ پس مصرفی گم نمی‌شود.

## قبل از شروع

لازم دارید:

- **دو سرور**، هر کدام با IP عمومی. سرور A پنلی است که دارید و سرور B نود می‌شود.
- **پورت‌های باز روی سرور B:** پورت پنلی که انتخاب می‌کنید (TCP) و پورت تونل‌هایی که آنجا می‌سازید.
- **راهی از A به B:** سرور A باید از اینترنت یا یک لینک خصوصی به پورت پنل سرور B برسد.

## قدم ۱: نصب W-UI روی نود

روی سرور B دقیقاً مثل A نصب کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AbolfazlTafakori/w-ui/main/install.sh)
```

سؤال‌ها را مثل همیشه جواب دهید. برای نود دو چیز مهم است:

- **گواهی بگیرید.** پیش‌فرض، یعنی Let's Encrypt برای IP خود سرور، کافی است و گواهی دامنه هم همان‌قدر خوب است. این پنل هر بار که با نود حرف می‌زند همین گواهی را بررسی می‌کند، و همین است که نمی‌گذارد کسی سر راه توکن را بخواند.
- **آدرس Access URL را یادداشت کنید**، با پورت و مسیرش، که آخر نصب چاپ می‌شود. آدرس نود همین است.

لازم نیست روی پنل خود نود چیزی بسازید. خالی بگذاریدش؛ این پنل پرش می‌کند.

## قدم ۲: ساخت توکن روی نود

توکن راهی است که این پنل با آن ثابت می‌کند اجازه‌ی مدیریت نود را دارد. آن را روی نود بسازید، به یکی از این دو روش:

- **از ترمینال سرور B:**

  ```bash
  wui token issue --name "panel A"
  ```

- **از پنل خود نود:** با Access URL آن وارد شوید، به **نودها ← ساخت توکن** بروید، یک نام بدهید و کپی‌اش کنید. توکن‌ها در **تنظیمات ← احراز هویت ← توکن API** هم فهرست، غیرفعال و باطل می‌شوند.

توکن **فقط یک بار** نشان داده می‌شود. همین حالا کپی‌اش کنید؛ فقط هشِ آن ذخیره می‌شود و دیگر نمایش داده نمی‌شود. اگر گمش کردید، یکی دیگر بسازید و قبلی را روی نود در تنظیمات ← احراز هویت ← توکن API باطل کنید.

## قدم ۳: افزودن نود به این پنل

در پنل سرور A به **نودها ← افزودن نود** بروید. فرم سه بخش دارد: سرور، دسترسی و اعتماد، و هزینه و سهمیه.

| فیلد | چه بنویسید |
|---|---|
| **نوع** | برای نودی مثل همین، **پنل W-UI**. دو نوع دیگر در [پنل 3x-ui به‌عنوان نود](#پنل-3x-ui-به‌عنوان-نود) و [پنل پاسارگاد به‌عنوان نود](#پنل-پاسارگاد-به‌عنوان-نود) آمده‌اند. |
| **نام** | هر چه دوست دارید، مثل `Frankfurt` یا `node-2`. در فهرست تونل‌ها و در نام کانفیگ مشتری‌ها می‌آید. |
| **آدرس** | همان Access URL نود، همان‌طور که در مرورگر بازش می‌کنید، مثل `https://203.0.113.9:41873/Xk3pQ9vL2mT8/`، هم با پورت و هم با مسیر مخفی. بدون مسیر، نود *not found* جواب می‌دهد و پنل نیست نشان داده می‌شود. |
| **اجازه‌ی آدرس داخل شبکه‌ی همین سرور** | پیش‌فرض خاموش است. هر درخواست به نود توکنی با دسترسی کامل به یک پنل همراه دارد، پس آدرسی که اشتباهی تایپ شود و به داخل شبکه‌ی خود این سرور اشاره کند رد می‌شود. فقط وقتی روشنش کنید که نود واقعاً روی یک شبکه‌ی خصوصی تحت کنترل شماست. |
| **توکن دسترسی** | توکن قدم ۲. |
| **بررسی گواهی** | وقتی نود گواهی واقعی دارد، یعنی Let's Encrypt برای IP یا دامنه‌اش که پیش‌فرض نصب‌کننده است، روی **بررسی عادی** بماند. حالت‌های دیگر در [سه حالت بررسی گواهی](#بررسی-گواهی) آمده‌اند. |
| **نام TLS (SNI)** | اختیاری. نامی که وقتی آدرس IP است در دست‌دهی TLS خواسته می‌شود. وقتی گواهی نود برای یک دامنه است، یا وقتی شبکه‌ی بین دو سرور اتصال TLS بی‌نام را قطع می‌کند، که بعضی شبکه‌های فیلترشده چنین می‌کنند، پرش کنید. |
| **ضریب مصرف** | `1`، مگر اینکه این سرور برای مشتری گران‌تر یا ارزان‌تر حساب شود؛ [پایین‌تر](#ضریب-مصرف) آمده. |
| **سقف ترافیک ماهانه (گیگابایت)** | فقط اگر هاستینگ ترافیک ماهانه‌ی نود را محدود می‌کند؛ [پایین‌تر](#سقف-ترافیک-ماهانه) آمده. |

ذخیره کنید. ظرف چند ثانیه ردیف **آنلاین** می‌شود، با نسخه، مدت روشنی، پردازنده، حافظه و تأخیر نود. **بررسی فوری** همان لحظه نود را بررسی می‌کند.

اگر **آفلاین** نشان داد، وضعیت می‌گوید از کدام نوع است: *refused* یعنی پورت بسته یا اشتباه است، *no answer* یعنی فایروال یا IP اشتباه، *wrong credentials* یعنی توکن اشتباه، و *answered but is not a panel* یعنی آدرس اشتباه است و چیز دیگری روی آن پورت جواب می‌دهد. بررسی‌ها در [وقتی نود ساکت می‌شود](#وقتی-نود-ساکت-می‌شود) آمده‌اند.

## صفحه‌ی نودها

نوار بالا تعداد **نودها**، تعداد نودهای **آنلاین** و **آفلاین** و **میانگین تأخیر** تا آنها را نشان می‌دهد. کنار **افزودن نود** دو دکمه‌ی دیگر هست: **مرجع صدور این پنل** برای [mutual TLS](#اثبات-هویت-پنل-mutual-tls،-اختیاری)، و **ساخت توکن** برای وقتی که خود *این* پنل قرار است نود پنل دیگری باشد.

| ستون | چه نشان می‌دهد |
|------|----------------|
| **عملیات** | ⚡ **بررسی فوری** همان لحظه نود را بررسی می‌کند؛ ⤓ **از این نود بخواه خودش را به‌روز کند** ([به‌روزرسانی نود](#به‌روزرسانی-نود) را ببینید)؛ برای نود W-UI، 3x-ui یا پاسارگاد **وارد کردن کاربران**؛ ✎ ویرایش؛ 🗑 حذف. |
| **فعال** | کلید روشن و خاموش. نود خاموش همگام نمی‌شود و تونل تازه‌ای رویش ساخته نمی‌شود. |
| **نام** | نام نود، با نوعش و روش بررسی گواهی‌اش. ردیف خود این سرور علامت پنل فعلی را دارد. |
| **آدرس** | جایی که به آن می‌رسید. |
| **وضعیت** | **آنلاین** یا **آفلاین** با دلیل، و **ترافیک تمام شد** وقتی سقف ترافیکش مصرف شده. ردیف این سرور **در حال اجرا** نوشته می‌شود. |
| **پردازنده** · **حافظه** · **نسخه** · **مدت روشنی** | همان‌طور که نود گزارش می‌دهد. |
| **ترافیک** | آنچه در این دوره جابه‌جا کرده، در کنار سقفش اگر تعیین شده باشد. |
| **تأخیر** · **آخرین بار** | زمان رفت‌وبرگشت آخرین بررسی، و آخرین باری که نود جواب داده. |

روی گوشی جدول به یک کارت برای هر نود تبدیل می‌شود. با لمس کارت عددهایش را می‌بینید و منوی ⋮ همان عملیات را دارد.

## قدم ۴: ساخت تونل روی نود

به **اینترفیس‌ها ← افزودن اینترفیس** بروید و در فیلد **سرور** به جای *همین سرور* نود را انتخاب کنید. بقیه‌ی فرم مثل تونل همین سرور است: پروتکل، پورت، ساب‌نت و اندپوینت، که IP عمومی نود یا نامی است که به آن اشاره می‌کند.

پنل در دور بعدی تونل را برای نود می‌فرستد و نود بالایش می‌آورد. ردیف تونل می‌گوید روی کدام سرور است. تونل را بعداً نمی‌شود به سرور دیگری برد، چون همه‌ی مشتری‌هایش کانفیگشان را از دست می‌دادند؛ پس اول سرور را انتخاب کنید.

نود W-UI می‌تواند چند تونل WireGuard، AmneziaWG و OpenVPN داشته باشد، و از OpenConnect، IKEv2، L2TP/IPsec و PPTP هر کدام یکی. این چهار پروتکل روی نود W-UI 3.0 یا جدیدتر لازم دارند. میزبان‌ها و گروه‌های میزبان روی تونل‌های نود دقیقاً مثل تونل‌های همین سرور کار می‌کنند.

## قدم ۵: گذاشتن مشتری روی نود

به **کلاینت‌ها ← افزودن کلاینت‌ها** بروید و زیر **سرورهایی که این مشتری می‌تواند استفاده کند** هر تونلی را که مشتری اجازه دارد تیک بزنید: روی این سرور، روی نود، یا هر دو. حجم، تاریخ پایان و تعداد کاربر مال مشتری است و بین همه‌ی آنها مشترک است.

هر فایلی که مشتری دارد روی هر تونلی که به آن دسترسی دارد حساب خودش را می‌گیرد، و لینک اشتراک برای هر کدام یک کانفیگ به اپ می‌دهد. مصرف همه‌ی سرورها روی همان یک حجم جمع می‌شود و وقتی تمام شد، مشتری همه‌جا قطع می‌شود.

کارهای گروهی، مثل وصل کردن مشتری‌های موجود به یک تونل یا جابه‌جا کردن یک گروه، بین سرورها هم همین‌طور کار می‌کنند.

### اتصال هم‌زمان، بین سرورها

**کاربران** پلن، یعنی اتصال‌هایی که هم‌زمان مجاز است، مال مشتری است، نه مال یک سرور. پنل هر سه ثانیه از هر نود می‌پرسد کدام ورودها رویش زنده‌اند، که برای هر نشست چند بایت است و نه کل وضعیت، آن را به آنچه کرنل خودش می‌بیند اضافه می‌کند و اتصال‌های مشتری را روی همه جمع می‌زند. یک فایل WireGuard روی این سرور و یک ورود OpenVPN روی نود دو اتصال حساب می‌شوند. وقتی بیشتر از اجازه‌ی پلن وصل باشند، جدیدترین اتصال دو دقیقه کنار گذاشته می‌شود. روی این سرور این کار مستقیم انجام می‌شود. روی نود، پنل همان لحظه به نود خبر می‌دهد (`/api/node/hold`) و با هر دور دوباره، و نود نشست را می‌بندد و دستگاه را تا آن موقع بیرون نگه می‌دارد. گزارش پنل می‌نویسد `connection limit reached; device held off … on="node 2"` و گزارش نود `device held off by the panel`.

اگر نودی در دسترس نباشد، آخرین گزارشش ۳۰ ثانیه معتبر می‌ماند و بعد شمرده نمی‌شود؛ پس دستگاه مشتری روی نودی که در دسترس نیست از طریق آن کنار گذاشته نمی‌شود. در سمت نود، وقتی ۴۵ ثانیه از پنلش خبری نشود، خودش با همان چیزی که می‌بیند مشتری‌ها را به سقف نگه می‌دارد، تا یک قطعی کوتاه بین دو سرور راهی برای دور زدن سقف نباشد. هر دو طرف باید همین نسخه یا جدیدتر باشند.

## پنل 3x-ui به‌عنوان نود

سروری که 3x-ui نسخه‌ی ۲.۰ یا جدیدتر دارد، بدون نصب W-UI می‌تواند نود باشد. نسخه‌های پیش از ۳.۰ با نام کاربری و رمز وصل می‌شوند؛ نسخه‌های ۳.۰ تا ۳.۲ با توکن API، به‌علاوه‌ی نام کاربری و رمز برای اوت‌باند (و روی ۳.۰ برای لینک‌ها)؛ و ۳.۳ به بعد فقط با توکن API.

1. در پنل 3x-ui، نسخه‌ی ۳ یا جدیدتر، از **Settings → API tokens** یک توکن API بسازید.
1. این‌جا **افزودن نود** را بزنید، نوع را **پنل 3x-ui (ثنایی)** بگذارید و آدرس ورود را با مسیر مخفی (`https://IP:port/path`، همان‌طور که 3x-ui چاپ می‌کند) و توکن، یا نام کاربری و رمز، وارد کنید.
1. ظرف بیست ثانیه هر اینباند با پروتکل، پورت و ترنسپورتش در صفحه‌ی اینترفیس‌ها زیر تب همان نود ظاهر می‌شود. مشتری را مثل هر تونل دیگری رویش بگذارید.

بعد از آن:

- **هر فایل یک کلاینت روی پنل 3x-ui است** با نام `wui-` و یک شماره. به کلاینت‌هایی که گرداننده‌ی خود آن پنل ساخته دست زده نمی‌شود.
- **مصرف هر بیست ثانیه از شمارنده‌های 3x-ui خوانده می‌شود** و با ضریب مصرف نود به مصرف کل مشتری اضافه می‌شود.
- **حجم و انقضا دست همین پنل است.** کلاینت آن‌جا محدودیتی از خودش ندارد؛ وقتی حجم یا زمان مشتری این‌جا تمام شود، آن‌جا خاموش می‌شود و با تمدید دوباره روشن.
- **یک کاربر برای هر فایل** همان محدودیت IP کلاینت در آن پنل است، یعنی ۱، که خود 3x-ui اعمال می‌کند. مشتری بدون محدودیت دستگاه آن‌جا هم محدودیتی ندارد.
- **لینک‌ها همان‌هایی است که 3x-ui برای کلاینت می‌سازد**، با آدرس، کلیدها و ترنسپورت خودش، و در همان یک لینک اشتراک مشتری می‌آیند. اگر اینباند آن‌جا عوض شود، لینک‌ها ظرف یک دور به‌روز می‌شوند.
- **اینباند در خود پنل 3x-ui ویرایش می‌شود**، نه این‌جا. اینباندی که آن‌جا حذف شود این‌جا حذف‌شده نشان داده می‌شود و از اشتراک بیرون می‌رود، و تونلش وقتی مشتری‌ای رویش نماند پاک می‌شود.
- **محدودیت سرعت** روی نود 3x-ui اعمال نمی‌شود، چون xray برای هر کاربر نرخ جدا ندارد.

## پنل پاسارگاد به‌عنوان نود

پنل پاسارگاد نسخه‌ی ۱.۰ یا جدیدتر، که نود خودش به آن وصل است، به همین شکل می‌تواند نود باشد: با نام کاربری و رمز یک ادمین، یا از نسخه‌ی ۵.۲ با کلید API.

1. در پنل پاسارگاد از **API keys** یک کلید API بسازید، یا نام کاربری و رمز یک ادمین را آماده کنید.
1. این‌جا **افزودن نود** را بزنید، نوع را **پنل پاسارگاد** بگذارید و آدرس (`https://IP-یا-دامنه:پورت`) و کلید، یا نام کاربری و رمز، را وارد کنید.
1. ظرف بیست ثانیه هر اینباند در صفحه‌ی اینترفیس‌ها زیر تب همان نود ظاهر می‌شود.

بعد از آن مثل 3x-ui است، به روش خود پاسارگاد:

- **هر فایل یک کاربر است** با نام `wui_` و یک شماره، در گروهی که این پنل فقط برای همان اینباند نگه می‌دارد (`wui <اینباند>`). به کاربرهایی که گرداننده‌ی خود پاسارگاد ساخته دست زده نمی‌شود.
- **اطلاعات اتصال را خود پاسارگاد می‌سازد** و لینک‌ها همان‌هایی است که اشتراک پاسارگاد برای کاربر می‌دهد.
- **مصرف همان ترافیک مصرف‌شده‌ی کاربر است** که هر بیست ثانیه خوانده می‌شود. حجم و انقضا دست همین پنل است و وقتی حجم مشتری این‌جا تمام شود، کاربرش آن‌جا غیرفعال می‌شود.
- **پاسارگاد محدودیت IP از خودش ندارد**، پس یک کاربر برای هر فایل روی این نود اعمال نمی‌شود.
- **اینباند Shadowsocks-2022 یک کاربر ثابت دارد** با نام `wuikeep_` و یک شماره، که کلیدش به کسی داده نمی‌شود. نود پاسارگادی که چنین اینباندی را بدون کاربر بالا بیاورد، بعداً هیچ کاربری رویش نمی‌گیرد و همگام‌سازی همه‌ی کاربرهای آن نود، از جمله کاربرهای خود گرداننده‌اش، خطا می‌دهد. این کاربر را پاک نکنید.

نام‌هایی که روی نود ساخته می‌شوند برچسب شش‌حرفی همین نصب W-UI را دارند (`wui-<tag>-<n>` روی 3x-ui و `wui_<tag>_<n>` روی پاسارگاد)، تا دو پنل W-UI روی یک نود کاربرهای هم را پاک نکنند.

## وارد کردن کاربرهای خود پنل

پنل 3x-ui یا پاسارگاد معمولاً پیش از نود شدن کاربر دارد. درست بعد از افزودن نود، و هر وقت بعد از آن با **وارد کردن کاربران** روی ردیف همان نود، کاربرهایش با مصرف، انقضا و اینباندهایشان فهرست می‌شوند. همه را وارد کنید یا آنهایی را که تیک می‌زنید. اینباندهای نود باید پیش‌تر زیر تبش آمده باشند، که تا بیست ثانیه بعد از افزودن نود طول می‌کشد.

- **برای خود کاربر چیزی عوض نمی‌شود.** اطلاعات اتصال، لینک‌ها و اشتراکی که صاحبش به او داده همان می‌ماند و بدون قطعی کار می‌کند. لینک اشتراک مشتری در این پنل همان لینک‌ها را کنار هر سرویس دیگری که به او فروخته‌اید دارد.
- **حجم، مصرف، انقضا و محدودیت IP همراهش منتقل می‌شود** و از آن به بعد دست همین پنل است. محدودیت‌های خودش روی آن پنل برداشته می‌شود تا آن پنل با عددهایی که دیگر این‌جا نگه داشته نمی‌شوند قطعش نکند. وقتی این‌جا تمام شود، آن‌جا خاموش می‌شود و با تمدید دوباره روشن.
- **کاربری که آن‌جا دستی خاموش شده خاموش می‌ماند**، این‌جا هم. **مشتری‌ای که این‌جا حذف شود** آن‌جا همان‌طور که بود می‌ماند.
- در **3x-ui** کلاینت‌هایی که یک شناسه‌ی اشتراک (subId) مشترک دارند یک مشتری حساب می‌شوند. در **پاسارگاد** هر کاربر یک مشتری است؛ گروه‌هایش دست صاحبش می‌ماند و لینک‌هایش همه‌ی اینباندهای آن گروه‌ها را دارد.
- کاربرهایی که بعداً آن‌جا ساخته شوند خودکار منتقل نمی‌شوند؛ با همان دکمه واردشان کنید. کاربرهایی که یک پنل W-UI ساخته هیچ‌وقت در این فهرست نمی‌آیند.

### از نود W-UI

پنل W-UI هم معمولاً پیش از نود شدن تونل و مشتری خودش را دارد. دکمه‌ی **وارد کردن کاربران** روی ردیف نود، این مشتری‌ها را با مصرف، انقضا و تونل‌هایشان فهرست می‌کند و آن‌ها را مشتری همین پنل می‌کند.

- **چیزی که دست مشتری است عوض نمی‌شود.** تونل‌ها و مشتری‌ها این‌جا دقیقاً همان‌طور ساخته می‌شوند که روی آن پنل هستند: همان کلیدها، پورت‌ها، آدرس‌ها و رمزها. اتصال کسی قطع نمی‌شود و لازم نیست برای کسی کانفیگ تازه بفرستید.
- **هر تونل با همه‌ی مشتری‌هایش منتقل می‌شود.** اگر یک مشتری را تیک بزنید، هر کسی که با او تونل مشترک دارد هم می‌آید و بعد از انتقال اسمشان نشان داده می‌شود. مشتری‌ای که روی آن پنل فایلی روی اینباند Xray دارد سر جایش می‌ماند، چون آن فایل با او منتقل نمی‌شود.
- **حجم، مصرف، انقضا، محدودیت دستگاه، گروه‌ها و شناسه‌ی تلگرام و بله همراهشان می‌آید** و از آن به بعد دست همین پنل است. مصرفی که منتقل شده دوباره حساب نمی‌شود.
- **لینک ساب مشتری از این به بعد لینک همین پنل است.** لینکی که آن پنل داده بود دیگر مال او نیست؛ لینک این‌جا را برای مشتری بفرستید. شناسه‌ی ساب هم منتقل می‌شود، مگر این که مشتری دیگری در این پنل همان را داشته باشد.
- روی خود آن پنل همان تونل‌ها و مشتری‌ها می‌مانند، ولی از این به بعد برای همین پنل اجرا می‌شوند و آن‌جا قابل ویرایش نیستند؛ مثل هر تونلی که پنل مدیر روی نودش می‌گذارد.
- **هر دو پنل باید همین نسخه یا جدیدتر باشند.** نود قدیمی‌تر جواب می‌دهد که تا به‌روز نشود نمی‌تواند مشتری‌هایش را تحویل بدهد.
- اگر نود وسط کار رد کند یا جواب ندهد، چیزی نیمه‌کاره نمی‌ماند: هرچه این‌جا ساخته شده بود پاک می‌شود و مشتری‌ها روی نود می‌مانند. دوباره امتحان کنید.

## ساخت اینباند روی نود 3x-ui یا پاسارگاد

در صفحه‌ی اینترفیس‌ها **افزودن اینترفیس** را بزنید و اول سرور را انتخاب کنید. فهرست پروتکل‌ها همان چیزهایی را دارد که آن پنل در نسخه‌ی خودش ارائه می‌کند:

| پنل | پروتکل‌ها |
|---|---|
| 3x-ui | VLESS، VMess، Trojan، Shadowsocks، HTTP (2.0)؛ WireGuard، SOCKS و dokodemo-door (2.5)؛ mixed و tunnel به جای آن دو (2.8)؛ Hysteria2 (2.9)؛ MTProto (3.4)؛ TUIC و AmneziaWG (3.8)؛ MASQUE (3.10) |
| پاسارگاد | VLESS، VMess، Trojan، Shadowsocks، Hysteria2، WireGuard، mixed، SOCKS، HTTP، tunnel، dokodemo-door |

فرم همان چیزهایی را می‌پرسد که فرم خود آن پنل می‌پرسد: تنظیمات هر پروتکل، ترنسپورت (TCP، WebSocket، gRPC، HTTPUpgrade، XHTTP، mKCP)، TLS با فایل یا متن گواهی، Reality، fallback و sniffing؛ روی 3x-ui حجم، انقضا و ریست ترافیک خود اینباند، و روی پاسارگاد میزبانی که لینک‌ها از آن نوشته می‌شوند. کلیدهای Reality، WireGuard، Shadowsocks 2022 و MTProto همین‌جا ساخته می‌شوند.

اگر xray آن پنل با اینباند جدید درست بالا نیاید، اینباند دوباره برداشته می‌شود و دلیلش نشان داده می‌شود، تا کاربرهای خود گرداننده‌ی آن پنل قطع نشوند. اینباندهای SOCKS، HTTP، mixed و tunnel ساخته می‌شوند ولی مشتری نمی‌گیرند، چون حساب جدا برای هر کاربر ندارند.

## بررسی گواهی

توکن به این پنل اجازه می‌دهد کلیدهای همه‌ی مشتری‌های آن نود را بخواند، پس اینکه *چه کسی* در آن آدرس جواب می‌دهد مهم است. سه حالت هست:

| حالت | چه وقت |
|---|---|
| **بررسی عادی** | نود گواهی‌ای دارد که مرورگر می‌پذیرد، یعنی Let's Encrypt برای IP یا دامنه‌اش. پیش‌فرض نصب‌کننده همین است و انتخاب درست هم همین. |
| **فقط یک گواهی مشخص** | نود گواهی خودامضا یا خصوصی دارد. **بخوانش** را بزنید تا اثر انگشتی که آدرس همین حالا نشان می‌دهد گرفته شود، و آن را با خود نود مقایسه کنید: روی سرور B دستور `openssl x509 -in /etc/wui/certs/<name>/fullchain.pem -noout -fingerprint -sha256`. از آن به بعد این پنل همان گواهی را می‌پذیرد و هیچ گواهی دیگری را، هر که امضایش کرده باشد. |
| **اصلاً بررسی نکن** | فقط روی لینک خصوصی‌ای که کس دیگری به آن نمی‌رسد. هر کسی بین دو سرور می‌تواند همه چیز را، از جمله توکن را، بخواند و عوض کند. |

### اثبات هویت پنل (mutual TLS، اختیاری)

نود به‌طور پیش‌فرض هر درخواستی را که توکن را داشته باشد می‌پذیرد. برای اینکه **فقط همین پنل** را بپذیرد، حتی اگر توکن از یک لاگ یا بکاپ بیرون برود:

1. روی سرور A به **نودها ← مرجع صدور این پنل ← نشانش بده** بروید و آن را کپی کنید.
1. روی پنل خود سرور B به **تنظیمات ← احراز هویت ← پنلی که اجازه‌ی مدیریت این یکی را دارد** بروید، آن را بچسبانید و ذخیره کنید.
1. روی سرور A نود را ویرایش کنید و **بررسی، و اثبات هویت این پنل** را انتخاب کنید.

از آن به بعد نود هر درخواستی را که گواهی کلاینت این پنل را نداشته باشد رد می‌کند (`this node only accepts a managing panel that presents a client certificate`). با خالی کردن آن فیلد روی نود، این حالت دوباره خاموش می‌شود.

## ضریب مصرف

ضریب مصرف می‌گوید هر گیگابایت از این نود چقدر از حجم مشتری کم کند. `1` همان‌طور که هست حساب می‌کند. `2` دو برابر حساب می‌کند، برای سروری که پهنای باندش برایتان گران‌تر است یا نمی‌خواهید زیاد استفاده شود. `0.5` نصف حساب می‌کند. این ضریب پیش از کم شدن از حجم مشتری در مصرفی که نود گزارش می‌دهد ضرب می‌شود؛ پس پلن ۱۰ گیگابایتی روی نودی با ضریب `2` با ۵ گیگابایت ترافیک تمام می‌شود. ردیف هر دستگاه در جدول مصرف مشتری هم به همین شکل ضرب می‌شود، و جمع ردیف‌ها هنوز بایت به بایت با مصرف یکی است.

## سقف ترافیک ماهانه

اگر هاستینگ ترافیک ماهانه‌ی سرور B را محدود می‌کند، سقف را این‌جا بگذارید و در **شروع دوباره در روز** روزی از ماه را که سقف از نو شروع می‌شود: از 1 تا 28، یا `0` اگر خودتان دستی پاکش می‌کنید. وقتی نود این مقدار ترافیک را جابه‌جا کرد، پنل همه‌ی مشتری‌ها را تا شروع دوره‌ی بعد از آن برمی‌دارد و ردیف نود **ترافیک تمام شد** نشان می‌دهد. مشتری‌هایی که سرور دیگری هم دارند، آنجا کار می‌کنند.

## به‌روزرسانی نود

نودها را همراه پنل به‌روز کنید. نودی که از پنلش قدیمی‌تر است هنوز همگام می‌شود و فیلدهایی را که نمی‌شناسد نادیده می‌گیرد، ولی سقف اتصال بین سرورها، برداشتن تونل‌های حذف‌شده و پروتکل‌هایی که در 3.0 آمده‌اند لازم دارند هر دو طرف یک نسخه باشند.

روی ردیف نود ⤓ **از این نود بخواه خودش را به‌روز کند** را بزنید و تأیید کنید. پنل از نود *می‌خواهد* خودش را به‌روز کند؛ نود نسخه را از GitHub می‌گیرد و امضایش را با کلیدی که داخل برنامه‌ی خودش هست بررسی می‌کند. چیزی از این پنل فرستاده نمی‌شود، پس پنلی که نفوذ شده باشد نمی‌تواند روی نودها کد بفرستد. راه دیگر این است که روی سرور B دستور `w-ui update` را اجرا کنید.

::: warning نودهایی با نسخه‌ی 2.0.0 تا 2.6.0
نودی که روی هر کدام از این نسخه‌هاست توکن پنل مدیرش را رد می‌کند. در دسترس نیست نشان داده می‌شود، مشتری‌هایی که این‌جا اضافه می‌شوند هرگز به آن نمی‌رسند، ترافیکش شمرده نمی‌شود، و دکمه‌ی به‌روزرسانی هم به آن نمی‌رسد. یک بار روی خود سرور نود دستور `w-ui update` را اجرا کنید. از 2.6.1 به بعد نود دوباره از همین‌جا مدیریت و به‌روز می‌شود.
:::

## حذف نود

نود را از صفحه‌ی **نودها** حذف کنید. روی سرور B چیزی عوض نمی‌شود: تونل‌هایش را اجرا می‌کند و مشتری‌هایش تا وقتی روی پنل خود نود حذفشان نکنید کار می‌کنند. توکنش هم تا وقتی آنجا در تنظیمات ← احراز هویت ← توکن API باطلش نکنید معتبر می‌ماند.

برای اینکه تونل‌های نود را اول از همین‌جا حذف کنید، آنها را در **اینترفیس‌ها** حذف کنید. هر دور تونل‌هایی را که نود هنوز باید داشته باشد نام می‌برد، پس تونل حذف‌شده ظرف یک دور، همراه با دستگاه شبکه‌اش، روی نود برداشته می‌شود.

## وقتی نود ساکت می‌شود

ردیف نود می‌گوید سکوت از چه نوعی است. این‌ها را به ترتیب بررسی کنید:

1. **سرور A به نود می‌رسد؟** روی A دستور `curl -sk https://NODE-IP:PORT/api/meta` را اجرا کنید؛ باید JSON بگیرید. اگر timeout شد، مشکل از شبکه یا فایروال روی B است (`ufw status` یا پنل فایروال هاستینگ). *connection refused* یعنی پورت اشتباه است یا پنل نود خاموش است (`w-ui status` روی B).
1. **اطلاعات ورود اشتباه.** توکن باطل شده یا اشتباه تایپ شده. روی B یکی تازه بسازید و نود را این‌جا ویرایش کنید.
1. **گواهی رد شد.** در حالت *فقط یک گواهی مشخص*، گواهی نود عوض شده، چون گواهی خودامضا تمدید شده یا نود از نو نصب شده؛ اثر انگشت را دوباره بخوانید. در حالت *بررسی عادی*، گواهی IP تمدید نشده؛ روی B منوی `w-ui` را باز کنید و گزینه‌ی 20 را بزنید.
1. **جواب داد ولی پنل نیست.** چیز دیگری در آن آدرس جواب می‌دهد؛ پورت داخل Access URL را بررسی کنید.
1. **آنلاین است ولی تونل‌ها روی B ساخته نمی‌شوند.** در حین یک دور، روی A دستور `journalctl -u wui -f` را اجرا کنید؛ خط‌های `node …` دلیل را می‌گویند. روی B، تونل پورت آزاد لازم دارد و AmneziaWG ماژول خودش را. پیام‌ها همان پیام‌های تونل همین سرورند و در [خطاها](/fa/reference/errors) فهرست شده‌اند.

تا وقتی نودی در دسترس نیست، پنل همه‌ی اطلاعات را نگه می‌دارد و فقط مشتری‌های همان سرور متوجه می‌شوند. هر چه در این مدت مصرف کرده‌اند، وقتی نود برگشت شمرده می‌شود.

## پنل خود نود

سرور B یک پنل کامل باقی می‌ماند. می‌توانید واردش شوید، آنجا `w-ui` را اجرا کنید، از آن بکاپ بگیرید، و تونل‌ها و حساب‌هایی را که این پنل رویش گذاشته ببینید. این‌ها مدیریت‌شده علامت خورده‌اند و از این‌جا ویرایش می‌شوند، نه آنجا. بکاپ‌های زمان‌بندی‌شده‌ی نود مال خودش است و بازگردانی A، سرور B را بازنمی‌گرداند.
